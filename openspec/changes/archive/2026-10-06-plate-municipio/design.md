# Design: Plate Municipio

## Technical Approach

A copy of the `placaRenovacionMes` path from `archive/2026-10-04-vehicle-details-and-renewals`, one more key through every stop it already takes. No new module, no new seam. Column `placa_municipio text` (nullable) in migration `0026`; the INTERNAL tri-state contract (`VehiculoInput`, `vehicles.ts:56-64`) is extended, not redesigned.

## Architecture Decisions

| Decision | Options | Choice and rationale |
|---|---|---|
| Column type | `varchar(80)` / `text` + CHECK / plain `text` | Plain `text`, 80 enforced in `validateVehiculoInput`. Every free-text `vehiculo` column is `text` validated in code; the trust boundary is the validator, and the single-insert route never writes the key. |
| Normalization | Trim in form / trim in validator | Validator: a string is trimmed, `""` becomes `null` (explicit clear), length > 80 or a non-string non-null value throws `ClienteValidationError({ placaMunicipio })`. `undefined` stays absent (tri-state). |
| Gate | New key list / extend the existing one | Extend `sendsInternalVehiculoFields` (`!== undefined`, so `null` counts) and `COLLECTION_ONLY_FIELDS` in `api/customers/[id]/vehicles/route.ts` (refused for everyone, like its siblings). |
| Public exposure | Omit / allowlist | No edit: `PublicVehiculo`/`toPublicVehiculo` and `vehicleDescriptiveRows` are named allowlists, so the new column is hidden by default. Proven by poisoned fixtures, not by an edit. |
| Due-row display | Every row / placa rows only | Only rows with `kind === "placa"`: the municipio is where the PLATE renews; on a "seguro" row it is noise. See Open Questions. |
| Form layout | Third cell in `grid-cols-2` / own full-width row | Own row below the month/insurance grid inside "Uso interno": a third cell would wrap unevenly at 390px. |

## Interfaces / Contracts

`Vehiculo` gains a required `placaMunicipio: string | null`, so `tsc` forces every full-row fixture to name it. That is the intended forcing function, not churn.

## Testing Strategy

| Layer | What | Approach |
|---|---|---|
| Unit | Validator: `"  San Miguelito "`→trimmed, `""`/`"   "`→`null`, absent→absent, 81 chars→error, 80 accepted, number→error | `validation.test.ts` |
| Unit | Tri-state: update without the key has no `placaMunicipio` in SET; `null` clears; insert defaults `null`; gate true for `null`, false for `undefined` | `vehicles.test.ts`; mutation-verify by deleting the spread guard |
| Unit | Refusal: técnico POST/PATCH with the key (null included) → 403; single-insert POST → 400 | extend the `it.each` lists in `api/customers/route.test.ts`, `[id]/route.test.ts`, `[id]/vehicles/route.test.ts` |
| Unit | Leak: add `placaMunicipio: "SENTINEL-MUNICIPIO"` to every POISONED fixture (vehicles GET, `toPublicVehiculo`, customer page técnico props, order detail, print sheet) and assert the sentinel absent | Mutation-verify by temporarily spreading the full row into each allowlist; each sentinel test must go red by name |
| Component | Form sends trimmed value / `null` with grant, key absent without; row error shows; detail page and due row show it only for placa rows and only with grant | `CustomerForm.test.tsx`, page tests |
| E2E | `vehicle-details.e2e`: create with municipio; técnico edit keeps it; técnico sending it (null) → 403; admin `"  X "` stores `"X"`, `""` stores `null`. `vencimientos.e2e`: `listDueCandidates` returns the column | Injected-seam limit: the real INSERT/UPDATE and SELECT only run here |

Browser check at the LAN IP, 390px and 768px: an 80-char municipio wraps in the due card and table cell with no horizontal overflow (`responsive-layout` "No Horizontal Overflow at 390px"); the form row fits.

## Threat Matrix

N/A — no routing, shell, subprocess, VCS/PR automation, executable-file classification, or process-integration boundary.

## Migration / Rollout

Additive `ALTER TABLE "vehiculo" ADD COLUMN "placa_municipio" text;` no default, no backfill. Workshop PC runs `standalone.ps1` on deploy, or the page selecting the column errors. Down: drop the column.

`closed-order-lock` also adds a migration. Whichever merges second regenerates its migration (number and snapshot) on top of the other; never hand-renumber a snapshot.
